# Docker

Two images (API and web) and two Compose files: `docker-compose.yml` for
development, `docker-compose.prod.yml` for a single-host production
deployment behind Caddy. Build every image from the repository root, because
both apps depend on `packages/shared`.

## Images

### API — `apps/api/Dockerfile`

| Stage       | What happens                                                                                                                                                                |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `build`     | `npm ci` for the API workspace, then esbuild bundles `server.js`, `migrate.js` and `seed.js` into `dist/` (the shared package is compiled in) and copies the SQL migrations |
| `prod-deps` | `npm ci --omit=dev` for the API workspace only                                                                                                                              |
| `runtime`   | `node:22-bookworm-slim`, production dependencies + `dist/`, runs as the unprivileged `node` user                                                                            |

- Entrypoint: `node dist/server.js` on port 4000.
- `UPLOAD_DIR=/data/uploads`, declared as a volume and owned by `node`.
- Health check: `GET /api/health` every 30 s.
- The same image runs migrations (`node dist/migrate.js`) and the seed
  (`node dist/seed.js`).

### Web — `apps/web/Dockerfile`

| Stage     | What happens                                                                                                    |
| --------- | --------------------------------------------------------------------------------------------------------------- |
| `build`   | `npm ci`, then `next build` with `output: "standalone"` (server, traced dependencies and the self-hosted fonts) |
| `runtime` | the standalone server and static assets only, as the `node` user                                                |

- Entrypoint: `node apps/web/server.js` on port 3000.
- Build argument `API_INTERNAL_URL` (default `http://api:4000`): the
  `/api`, `/media` and `/cv` rewrites are resolved at build time. In
  production Caddy routes those paths to the API before they reach Next.js,
  so the rewrites matter only when the web container is used on its own.
- Runtime variables: `APP_URL`, `API_INTERNAL_URL`, `REVALIDATE_SECRET`.
- Health check: `GET /robots.txt` every 30 s.
- There is no `public/` directory to copy: icons, the web manifest and social
  images are generated by route handlers, and fonts are bundled from
  `src/fonts`.

Build them directly with:

```bash
docker build -f apps/api/Dockerfile -t portfolio-api .
docker build -f apps/web/Dockerfile -t portfolio-web .
```

`.dockerignore` keeps `node_modules`, build output, `.env*` (except the
example), uploads, backups, tests and docs out of the build context.

## Development Compose — `docker-compose.yml`

| Service    | Profile   | Purpose                                                                                    |
| ---------- | --------- | ------------------------------------------------------------------------------------------ |
| `postgres` | (default) | PostgreSQL 17 on `127.0.0.1:5432`; also creates `portfolio_test` for the integration tests |
| `mailpit`  | `mail`    | SMTP on `127.0.0.1:1025`, web inbox on http://localhost:8025                               |
| `migrate`  | `app`     | Applies migrations with the API image, then exits                                          |
| `api`      | `app`     | The API image with `.env`, the Compose database and an `uploads` volume                    |
| `web`      | `app`     | The web image on `127.0.0.1:3000`                                                          |

```bash
docker compose up -d postgres                     # database for `npm run dev`
docker compose --profile mail up -d               # + Mailpit
docker compose --profile app up --build           # everything in containers
docker compose --profile app run --rm api node dist/seed.js
docker compose down                               # stop (add -v to delete the data volumes)
```

Ports are bound to `127.0.0.1` only.

## Production Compose — `docker-compose.prod.yml`

| Service    | Image                        | Notes                                                                                        |
| ---------- | ---------------------------- | -------------------------------------------------------------------------------------------- |
| `caddy`    | `caddy:2-alpine`             | The only service with published ports (80, 443, 443/udp). TLS, compression, headers, routing |
| `web`      | `portfolio-web:${IMAGE_TAG}` | Starts after the API is healthy                                                              |
| `api`      | `portfolio-api:${IMAGE_TAG}` | `env_file: .env.production`; starts after `migrate` succeeds                                 |
| `migrate`  | `portfolio-api:${IMAGE_TAG}` | One-shot `node dist/migrate.js`; runs on every `up`                                          |
| `postgres` | `postgres:17-alpine`         | Data in the `postgres-data` volume; health-checked with `pg_isready`                         |

Volumes: `postgres-data`, `uploads`, `caddy-data` (certificates),
`caddy-config`. All services restart `unless-stopped`.

Start order: `postgres` (healthy) → `migrate` (completed) → `api` (healthy)
→ `web` (healthy) → `caddy`. A failed migration stops the API from starting
with a half-migrated schema.

Routing (`docker/Caddyfile`): `/api/*`, `/media/*` and `/cv` go to
`api:4000`, `/internal/*` answers 404, everything else goes to `web:3000`,
and `www.` redirects to the bare domain.

Deployment, updates, backups and rollback are in `deployment.md`.
